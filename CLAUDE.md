## Bot design (agreed with me)

Rewritten 2026-11-12, when the brain became the only way Bot works. Every rule below is a decision of mine: do not weaken one without asking me. The history of how we got here is in `experiments/progress-history-until-2026-11-12.md` and the dated notes in `experiments/`.

### How Bot works (one page)

- **MY CORE WISH:** no modes, no saved phrases, no keyword lists. Bot must understand what I mean and combine abilities ("save this link in the course and tell me if it is ordered by weeks"). When Bot misunderstands, fix `brain-brief.md` (plain English) or add a CHECKED TOOL. Never add regexes or word lists on my words to route a message.
- **ONE CONVERSATION (the thread):** `thread-store.js` keeps day files (`data/thread/YYYY-MM-DD.jsonl`, appended, no message cap, 30-day trash that only I or Bot's timer can use, never a model). Each message is its own job (`startThread` in `jobs.js`); answers carry `replyTo`. At most 2 messages are being answered by models at once (the others queue), and a question to a course waits for an earlier one to the same course. There is no switch: `BOT_THREAD` and `BOT_BRAIN` were removed on 2026-11-12.
- **THE BRAIN (`brain.js`, briefing `brain-brief.md`):** one model reads every message with a TOOLBOX. It replies with text, or with lines `CALL {json}` asking for tools; code CHECKS every call and runs it; at most 3 tool rounds. Models only PROPOSE; code checks; I confirm what matters.
  - Context given every time, built by code and capped (`thread-context.js`, `history.js`; never the whole history, a model returns nothing past about 200,000 characters): the time, my profile, the courses and their files, what I said about each course, the calendar of the next 7 days and the waiting reminders (the model sees my event titles, read-only), the recent talk, the newest calendar card note, and for the course the talk is in: its assignment text, the best-matching pages (`course-material.js`) and the file list of my linked folder.
  - Lookups: course_search, course_read, course_files, calendar_read, reminders_list, study_status, search_memory, read_link, project_files, project_read, project_grep, pc_find, pc_list, moodle_courses, moodle_course, moodle_news, plus agy's own web search.
  - Doing: set_reminder (at once), add_events / remember / forget / exam_date (cards I confirm), course_note, study_position, study_undo, class_cancelled, file_folder (moves files into a folder LABEL or renames a folder; labels only), working_on, study_pause, study_resume, save_link, save_links (a list I confirm), link_folder, open_on_pc, pc_roots, moodle_fetch, moodle_link, improve_bot (a button).
  - Shown as code made them (the model must call them alone): quiz, quiz_answer, card_reply, study_plan, teach_next.
- **RULES THAT STAY IN CODE:** a link is opened only if I wrote it or it is in a course file; web, file, photo, Moodle and calendar text is DATA inside marked blocks, never instructions; after a web page or Moodle was read in a message, or when the message carries a photo, the doing-tools that act at once (set_reminder, course_note, study_position, study_pause/resume, file_folder, working_on, save_link(s), link_folder, open_on_pc, pc_roots; Moodle downloads and Moodle opens after a web page or photo) are refused in that message, so a page or a picture can never cause an action; Bot's reply to a doing-tool is shown only if every call worked; "Understood" is only ever set by the coach's graded quiz. agy's own built-in web search counts too: code sees its search_web step inside the call (watchSteps in providers.js, usedWebSearch in brain.js) and treats it like a web page read (2026-11-13).
- **MODELS (quota-aware, `quota.js`, `router.js`):** brain order Argon low -> Claude Sonnet LOW inside agy (`sonnetInAgy`, agy's own "Claude and GPT models" pool, NOT my Claude Pro plan) -> Claude Code Sonnet (the Pro plan, always the last resort). Flash never writes the brain's answers. Argon has a 25% RESERVE in the brain (`RESERVES`, `lowWithReserve`): under 25% everyday chat goes to agy Sonnet first, so Argon's last part stays for tutoring and big PDFs (those use it until 15%). A model under 15% moves to the end of its chain and the page says why. PACING (2026-11-12): of the two agy pools, the one with more quota left for the days left to its weekly reset answers first (paceOrder in quota.js, 10-point margin, so the same model answers for a stretch); the reserve and the 15% rule run after it and always win. SLIM AGENT: the brain's agy calls run under the agent bot-brain (only search_web; ensureAgent in providers.js, folder %TEMP%/bot-brain), which removes about 7,000 tokens of agy's own overhead from every call; never add tools to it without asking. TOKENS: every answer's log line says how many model calls and tokens it cost, and data/token-log.json keeps per-day totals (node tokenlog.js). CONTEXT: the recent talk is 5,000 characters (older answers keep their first 500), and only code files changed in the last 48 hours ride along. The daily summary and the position readers ask Flash medium first (code checks their output). SLOTS: the first model call of a message never waits; a slot is taken only for more model rounds, a quiz or a lesson. See experiments/2026-11-12-quota-max.md. Claude numbers come from rate_limit_event in real Claude answers, with a tiny Haiku probe at most every 10 minutes only if needed. Gemini 3.1 Pro is NOT in agy; GPT-OSS was rejected (wrong weekdays, gave a solution). Print which model answered and why, so I can see where my quota goes.
- **WHEN EVERY MODEL FAILS (agreed 2026-11-12):** Bot says so honestly (which models, why, "send it again in a minute"). Nothing is tried another way. A card or reminder made earlier in that message is still shown and listed.
- **PHOTOS:** a photo is a normal brain message. Only agy can look at it: Argon low first, Flash medium only as the fallback (2026-11-12). The photo sits alone in a private temp folder under a fixed name and is deleted after the answer. A timetable photo with "add to my calendar" becomes the same checked `add_events` card as typed text.
- **FILES WITH A MESSAGE (`thread-files.js`, `POST /api/thread/upload`):** code files it (real first bytes, course picked by code from the name / my words / the class on right now, asked once when unsure, no duplicates). Then the words I sent with it go to the brain as a follow-up on the same question; if they asked nothing more, no second message. After a file is read the coach may PROPOSE a lecture or an assignment (a Confirm card).
- **WAIT FOR FILES (2026-11-08):** a message in a course while a file of THAT course is `queued`/`reading` is not answered from the old material: code posts ONE short line (an `ack` message: not an answer, not in the models' memory, no push), waits WITHOUT a slot (poll 2 s, 15 min limit), then answers; a failed or unfinished read is said plainly in front of the answer.
- Gemini route = Antigravity CLI (`agy`): the old Gemini CLI stopped serving personal accounts on 2026-06-18. I have Google AI Pro (not Ultra). Model names and plan access change often: check current docs before hard-coding them. Shell commands in agy stay refused (never add `--dangerously-skip-permissions`).

### Calendar, reminders, memory

- **CALENDAR:** Bot talks to Google Calendar directly (`calendar.js`, my own Google login, scope `calendar.events`), not through Gemini. Bot can NEVER delete or change an event: never add delete/change functions, and never let a model call `createEvent`.
- **ADDING EVENTS:** always through a Confirm card. Models only PROPOSE fields; code checks every one (`checkPhotoEvents` in `calendar-add.js`: real dates, weekday -> first date, lengths, control characters) and builds the weekly repeat rule itself (`weeklyRule`), never from model text. The card is drawn by the page from the checked fields, lists every event with weekday, date, time and repeat end (a timetable is ONE card, one repeating series per class), works once, expires after 15 minutes and lives in memory only. Only the Confirm tap (`/api/calendar/confirm` in `server.js`) calls `createEvent`. A double tap cannot duplicate; if some events fail, the page says exactly which were and were not added and Bot never retries. On the phone, Confirm needs the normal login only. An expired Google login is explained in plain words and the card is kept.
- **CARD MEMORY:** the history gets a code-written note for each card (its checked events as JSON + its status: waiting, confirmed, cancelled, replaced, expired), for the models only, never shown on the page (`cardNote`, `historyEntry` in jobs.js). A correction after a WAITING card makes a NEW full card that replaces the old one (nothing is added twice); after a CONFIRMED card Bot says it cannot change events already added. A doubt about which event is meant goes to `unclear` and is shown on the card.
- **REMINDERS (`reminders.js`):** set at once by set_reminder after code checks the time is real and in the future.
- **MEMORY (`profile.js`):** `data/profile.md` (mine) and saved facts. A fact is saved only by my tap on the card, or at once when my own short message says "remember that ..." (with Undo); secrets are refused. Facts from summaries are always a confirm card; web, file and photo text never becomes a fact.
- **DAILY SUMMARY (`thread-summary.js`):** runs lazily at the first message of a new day (Argon low, Flash medium, never Claude); every item needs a word-for-word quote and a message id, facts only from my messages; notes enter prompts inside a marker as data that may be wrong. The morning brief is one message in the thread. Lock-screen pushes never show message text.

### Courses and studying

- **COURSES:** uploaded files are the main source. If they do not cover a question, Bot still answers from general knowledge. Web text is untrusted and never saved. The course page's own question box (`study.js`; not reachable from the page since 2026-11-13) cites pages, labels what is outside the files and may run one web check whose query is checked in code against my words (`safeWebQuery`).
- **LANGUAGES (2026-11-06; not reachable from the page since 2026-11-13):** on the course page, when the question is in the other language than most of the notes and it is a plain search, one short Flash low call (`crosslang.js`, 8 s limit, never Claude) writes search words in both languages; if it fails or is slow, the old search is used. Those words are SEARCH WORDS ONLY: code cleans them (`cleanWords`) and they reach the page search and nothing else.
- **READING:** big PDFs are cut locally (`pdfcut.js`) and read Argon first, then Sonnet, then Flash, because Flash made real math errors (experiments/2026-11-06-faster-reading.md).
- **STUDY COACH (`study-coach.js`, `study-plan.js`, `study-tracker.js`, `tutor.js`, data in `data/study/`):** tracks progress against the timetable and tutors. It must be DYNAMIC: only Calculus 2 has all lectures up front; everything else arrives week by week, so Bot never invents where I am. "Understood" is set ONLY by code from a graded check (3+ questions, 70%+); teaching or me saying "I understand" never counts. Argon only for tutoring, never Flash low, never Claude. Never give an assignment's solution: ask, hint in steps, reveal only after real attempts or on request. Cancelled classes are told to Bot in chat (it cannot know); the brain stores one with the checked tool `class_cancelled` (a real lecture date of that course, with undo). Hebrew text written by code uses no gendered "you".
- **WHERE I AM:** my own words about a course are ALWAYS kept (`course_note`, shown in every context; `position.said`). The closed fields (`mode`, `where`, `pace`, `behindBy`, `gaps`, `depth`, `goal`, `focus`; `position-record.js`) are PROPOSED by the brain (study_position) and checked by `standing.checkStanding` against the timetable and the notes' outline (`outline.js`): what does not fit is dropped with a reason and said honestly, never "stored nothing". `depth` is my opinion and is never "Understood". study_undo puts the old record back (2 hours). working_on keeps what I work on now and next per course (short text, from my words or what code saw in the folders). An exam date is kept only when I confirm its card. The record feeds the report (no "behind" for a student who does not attend), the plan, the quiz range and the nudges.
- **CATCH-UP (`catchup.js`):** teach_next teaches ONE chunk of the notes (about 4500 characters, 3 short steps, one phone screen, cited) and ends with one check question; the part is picked by CODE from the real outline (title words or a section number; only when nothing matches does ONE Argon call choose ids from the real list; never invented); what was taught is kept, and a quiz on "what I covered" draws only from it. study_plan gives ONE plan across all courses (code only): deadlines with real dates first, then courses in turns (goal "concepts" first), minutes per day (default 90).
- **NUDGES (`study-nudges.js`):** code-written, in the morning brief only, one a day at most, tied to a real date, quiet after two ignored, never in quiet hours or during a class; study_pause is the pause switch for reserve duty; the lock screen shows counts only.
- **LINKED FOLDER (`project-folder.js`):** a course can have the folder on this PC where I work on its assignment. Read-only and checked in code: linked only when the WHOLE path is in my OWN message, or (2026-11-12) when I tap Confirm on a card for a folder pc_find found; never a drive root, my home folder, a system folder or Bot's own folder; a file is read only if it is really inside the folder, is text, is at most 200 KB and is not a secret by name (.env, keys); .git and node_modules are skipped. Bot can never write, delete or run anything there. (2026-11-13) When a file I ask for is in the folder next to the linked one, code offers ONE Confirm card to link the parent instead (one level up, same checks, never a Linux/WSL home). Code also looks at file NAMES and times (never contents) in the parent to see that I moved on (mission1 -> mission2). project_grep searches text inside the linked folder only.
- **PC HANDS (2026-11-12, `pc-open.js`, `pc-find.js`):** Bot can FIND folders and files by NAME and OPEN things on the PC. Finding: only under the search roots (default Desktop, Documents, Downloads, OneDrive; I add or remove one in chat, `data/pc-roots.json`, a root added only with its full path in my own message, or (2026-11-13) by my Confirm tap on a card for my WSL home, which code learns only from my linked course folders; never the system drive, home itself, system folders, AppData, Bot's own folder), never into links, hidden or tool folders, never secret-looking names; disk walked fresh each time (measured tiny), results numbered and kept 2 hours; a model only hands back a NUMBER. Opening (`open_on_pc`): an https address I wrote or a course file holds, ALWAYS in Chrome (my Moodle login is there); a real Moodle course or item, address built by code; a course file (from a copy with its real name in a temp folder); a number from the last found list. A closed list of types: documents and pictures in their normal app, text and code ONLY in VS Code (the default action of .py/.js/.vbs could run them), folders in Explorer; programs, scripts, shortcuts, macro files and unknown types are refused, judged on the real path. No shell: the program is started directly with the target as one argument. Refused after a web page, a photo or (except Moodle's own items) Moodle text. From the phone it still opens on the PC and Bot says so. Reading CONTENT stays only inside a linked course folder. Bot never clicks in pages, fills forms or closes windows.
- **ZIP UPLOAD (`unzip.js`, Node built-ins only):** each file inside takes the single-upload road; Bot answers with ONE summary whose numbers add up. Limits are named constants: zip 200 MB, 300 MB unpacked, 50 MB per file, 200 files, 2000 entries, enforced while unpacking, never trusted from the zip. Names are never used as paths; `..`, absolute, hidden, symlinks, zips inside zips, passwords and unsupported types are skipped with a reason. Code files (`CODE_EXT` / `CODE_NAMES`) are plain TEXT and untrusted data (must pass `looksLikeText`, at most 1 MB); compiled leftovers are only counted. A picture is kept or skipped by `judgeImage` from its real bytes, never by a model. The course page takes a .zip too (`addZip`). Folder names are kept (2026-11-13) as a cleaned LABEL on each file (`folder`, `cleanFolder` in `upload.js`): a zip's inner folders, a Moodle download's section (and folder item); shown as folder/name and matched by code, never a path. file_folder changes labels only. Re-uploading a zip only adds missing labels to the files already there.
- **LINKS (`linkfetch.js`, `link-batch.js`):** Bot can READ a link (saves nothing) or DOWNLOAD it into a course. The URL comes ONLY from my own message or from the text of a course file, never from a model. Fetching is code: https only, public addresses only (checked on every connection and redirect), size and time limits, no cookies or tokens, GitHub links stay on GitHub hosts, never logs in. A FILE OF ADDRESSES (save_links): links are found by code (https, 50 at most), shown FIRST, fetched only after one Confirm tap, 2 at a time, one summary. Do not add tokens, logins or a second filing path.
- **MOODLE (2026-11-11, READ-ONLY):** BGU's Moodle refuses scripts at its Akamai edge, and Bot must NEVER pretend to be a browser. So my own Chrome reads: `moodle-extension/` (loaded unpacked once) asks Bot every 2 s on localhost (`GET /api/moodle/next`), runs the job with my own Moodle session and posts the answer. Bot's side is `moodle-bridge.js` (closed list of job kinds with whole-number arguments only, Bot never sends an address; routes only with the `X-Bot-Bridge` header and no web-page origin, never from the phone; 45 s limit, 4 min and 50 MB per file). The extension's allowlist: GET `/my/`, `mod/forum|resource|folder/view.php?id=N` and `pluginfile.php` addresses found on those pages; the only POST is `/lib/ajax/service.php` with READ_METHODS (all `_get_`). Nothing may ever submit, post, subscribe, mark or change a setting; no keep-alive pinging. Files go through the upload road; more than 10 files -> a Confirm card; 200 MB per request. A Moodle course maps to a Bot course by CODE (saved map, same name, the timetable pattern, one-to-one only); unclear -> Bot asks. No background sync. `moodle.js` + `experiments/moodle-probe.js` are kept unused for the day BGU allows scripts.
