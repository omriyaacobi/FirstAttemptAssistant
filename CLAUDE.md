## Bot design (agreed with me)

- Bot picks a model **per task, by need**; it is not built around one model. Both CLIs take `--model`.
- Rough idea: simple tasks -> small cheap model (Claude Haiku / Gemini Flash); everyday work -> mid model (Claude Sonnet); hard reasoning -> strongest (Gemini 4 Argon or Claude Opus).
- Google Calendar does NOT go through Gemini: Bot talks to it directly with `calendar.js` (my own Google login, scope `calendar.events`). Reading is the front desk action `calendar`; adding is `addEvent` (see CALENDAR below). Bot can never delete or change an event.
- ROUTER v3 (current): a "front desk" (Gemini 3.8 Flash low via a pre-warmed `agy`, see `frontdesk.js` and `warmagy.js`; a second call starts if the first is slow, see `deskrace.js`) reads each message with the plain-English briefing in `router-brief.md` and decides: answer itself, ask a clarifying question, delegate to ONE destination from the fixed menu in `router.js`, or have the planner split it. Its reply must be plain JSON and is validated in code (never trust model output). If the Gemini front desk fails or hits its deadline, **Claude Haiku is the BACKUP front desk** (`claude -p`, about 4 s, same validation, its own briefing `router-brief-haiku.md` as system prompt), so calendar, reminder and memory actions are not lost; only if Haiku fails too (or the planner fails) does Claude Sonnet take the task. The old keyword rules were removed. Edit `router-brief.md` to change how it decides, and keep `router-brief-haiku.md` in step: a test fails if the two name different destinations or actions.
- INDEPENDENCE (agreed): I want to run and grow Bot from its web page without Claude Code. The page has: Improve Bot (self-edit with an automatic retry loop), Restart Bot (needs start-web.cmd), a chat button that hands "change yourself" requests to Improve Bot, and Push to GitHub (with confirmation; `gitops.js`, never force). Claude Code is still needed for protected files, installs/logins and recovery.
- PHONE IMPROVE (changed 2026-11-07 at my request): on the phone, Improve Bot and Restart need the normal login only. The PIN was removed (`BOT_ADMIN_PIN` is ignored). Push to GitHub is always PC-only.
- SELF-EDIT (agreed): Bot may propose changes to its own code, but ONLY through `selfedit.js`: private git worktree + restricted editor + code-enforced checks + my approval in the web page + fast-forward merge, never a push. Never let a model start an edit by itself, never let it touch the protected files listed in `selfedit.js`, and never weaken those checks without asking me. SECOND EDITOR (agreed 2026-11-06): the window also offers **Argon** (Gemini 4 Argon through `agy`, `makeArgonEditor` in `selfedit.js`) for PAGE-ONLY changes, so they spend Gemini quota and no Claude quota. It runs `agy` with `--mode accept-edits` (never `--dangerously-skip-permissions`), with TEMP/TMP pointed at an empty private folder, and the code audits every tool call (only read_file / edit_file / write_file; paths inside the private copy; writes only under `public/`). After the run the diff may only contain files under `public/` (new, deleted and renamed included; no links), and the real project, `.env` and the other private copies must be unchanged. - CALENDAR ADD (agreed, branch claude/calendar-add-5116af): Bot can add events, always through a Confirm card, for typed messages (front desk action `addEvent`, default length 1 hour) and for photos (a photo message still goes to Gemini; when my own words ask to add it to the calendar, the model returns strict JSON only, see `calendar-add.js`). Models only PROPOSE fields; code checks every one (real dates, weekday -> first date, lengths, control characters) and builds the weekly repeat rule itself (`weeklyRule` in `calendar.js`), never from model text. The card is drawn by the page from the checked fields, lists every event with weekday, date, time and repeat end (a timetable is ONE card, one repeating series per class), works once, expires after 15 minutes and lives in memory only. Only the Confirm tap (`/api/calendar/confirm` in `server.js`) calls `createEvent`; no model can. Double tap cannot duplicate; if some events fail, the page says exactly which were and were not added and Bot never retries. On the phone, Confirm needs the normal login only (no PIN): it only adds, shows everything first, and is single-use. An expired Google login is explained in plain words and the card is kept. Several events from text use `eventsJson` (same checks as a photo). MEMORY: the chat history gets a code-written note for each card (its checked events as JSON + its status: waiting, confirmed, cancelled, replaced, expired), for the models only, never shown on the page (`cardNote` in calendar-add.js, `historyEntry` in jobs.js). A correction after a WAITING card makes a NEW full card that replaces the old one (the old card can no longer be confirmed, so nothing is added twice); after a CONFIRMED card Bot says it cannot change events already added. A doubt about which event is meant goes to `unclear` and is shown on the card. The photo call has a time limit (`askAgyWithImage`). Photo text is untrusted. Never add delete/change functions, and never let a model call `createEvent`.

- ZIP UPLOAD (agreed 2026-11-07): a `.zip` sent with a message is opened by `unzip.js` (Node built-ins only, no package) and each file inside takes the single-upload road (`thread-files.js`: real first bytes, course picked by code or asked once, no duplicates); Bot answers with ONE summary. Limits are named constants in `unzip.js`: zip 200 MB, 300 MB unpacked in total, 50 MB per file, 200 files, 2000 entries; sizes are enforced while unpacking, never trusted from the zip. Names are never used as paths; `..`, absolute, hidden, symlinks, zips inside zips, passwords and unsupported types are skipped with a reason; a zip that expands past its declared size is refused whole. Zip contents are untrusted data. The study coach is not asked about each file of a zip. CODE ZIPS (2026-11-08): a zip from a programming course also gives source and project text files (`CODE_EXT` / `CODE_NAMES` in `unzip.js`: .c .h .cpp .py .js .java .sh .json .csv .yaml, Makefile, README, Dockerfile and similar). They are plain TEXT and untrusted data (never run, never instructions): each must pass `looksLikeText` on its real bytes (no NUL, valid UTF-8, few control characters, `sniffFile` says text) and be at most 1 MB (`MAX_CODE_BYTES`), so a PDF or program renamed .c is refused. They are filed under the end of their path (`src/parser.c`), the notebook reads them as text and adds the file name to each piece's search words, so a question naming a file finds it. Compiled leftovers (.o .a .so .dll .exe .class .pyc, node_modules, .git, build folders) are only COUNTED in one line, never listed. The summary is in the language of the message (reasons in Hebrew for a Hebrew message, names inside isolate marks), shows documents and code files apart, and lists at most 5 skipped files. Limits for documents are unchanged.
