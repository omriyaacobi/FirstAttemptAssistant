## Backup of data/ (2026-11-06, branch `claude/data-backup-0015e0`, merged and pushed)

Why: `data/` (chats, course files, memory, Google login) exists only on this PC and is git-ignored. If the PC fails it is gone.

- **Your choices:** destination = a folder inside a synced cloud app (OneDrive or Google Drive for desktop); protection = everything **encrypted** (so the Google login and chats are included but unreadable to the cloud company).
- **Concepts, plain English:** *encryption* (AES-256-GCM, built into Node) scrambles the file with a key made from your passphrase; without the passphrase nobody can open it, and a wrong passphrase or a damaged file is detected (the "GCM tag"). A *hash* (SHA-256) is a fingerprint of a file; Bot stores one per file and checks them all after writing, so a backup is proven, not assumed. A *synced folder* means the desktop app uploads whatever lands in that folder; Bot only writes a file there.
- **What it does:** `backup.js` packs all of `data/` into one file `bot-backup-YYYYMMDD-HHMMSS.botbak` (gzip, then encrypt), written as `.tmp` and renamed when complete, then reads it back and checks every fingerprint. Only then are old copies beyond the newest 5 deleted (only files with that exact name pattern, only in the backup folder). It only READS `data/`; the only things it writes there are `backup-status.json` and `backup.log`.
- **Schedule:** inside Bot (no Windows scheduled task, so nothing on the system was changed). 2 minutes after Bot starts, then hourly check; a copy is made when the last good one is over 24 h old, and a failed try is repeated after 1 h. All file work is async (one file at a time, yielding to the chat), so chats are not blocked. It only runs while Bot runs.
- **Set up (you do this, I never saw a secret):** add to `.env`: `BOT_BACKUP_DIR` (a folder in OneDrive/Drive; its parent must exist), `BOT_BACKUP_PASSPHRASE` (12+ characters you invent), optional `BOT_BACKUP_KEEP`. See `.env.example`. **Keep a copy of the passphrase outside this PC** (password manager or paper): `.env` dies with the PC, and without the passphrase the backup is useless. The folder must not be inside the project (public repo) or inside `data/`; Bot refuses that.
- **Commands:** `node backup.js run` (backup now), `status`, `verify` (restores the newest backup into a temp folder, compares it with the real `data/`, deletes the temp folder), `restore <backup-file> <new-empty-folder>` (refuses `data/`, refuses a non-empty folder, refuses `../` paths in a forged file). To recover on a new PC: copy the repo, put the passphrase in `.env`, restore into an empty folder, then copy its contents into a fresh `data/` yourself.
- **See it:** a line under the sidebar ("Last backup: ..." or "Backup FAILED: ... Last good copy: ...", hidden when backups are off), `GET /api/backup`, `data/backup.log`.
- **Tested:** 13 tests in `backup.test.js` (temp folders only: round trip, wrong passphrase, tampering, no readable secrets in the file, real restore compared file by file, pruning, failures, forged paths, schedule rules, the API line). **Real test:** a copy of your real `data/` (46 files, 49 MB, incl. the Google login) was backed up in 1.5 s to a 49.4 MB encrypted file, restored in 0.3 s into a temp folder, and all 46 files were byte-identical to the real ones (throwaway passphrase, real `data/` untouched, temp files removed).
- **Not verified:** with your real OneDrive/Drive folder (the sync app uploading a ~50 MB file), a backup taken while Bot is mid-chat-save (each file is read whole, and Bot writes by rename, so a torn file is unlikely but unproven), the page line in a browser.
