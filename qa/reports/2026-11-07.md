# QA run 2026-11-07 (everyday use, BOT_THREAD=on, own copy on port 3100)

Setup: empty `data/`, no `.env`, no Google login. Two made-up courses ("Linear Algebra Demo" with 2 text lectures, "Intro Programming Demo"), made-up homework and slides as text files. About 40 messages sent through `POST /api/ask` (English and Hebrew), uploads through `/api/thread/upload`, one short browser journey at 375 px. All text below is made up.

Important context: the copy has no timetable, so several study problems may show up mainly in the "no timetable yet" state. That is also exactly the state Omri's first days are in, so they still count.

## Bugs

### HIGH

**H1. Bot says it set a reminder when it did not (combined message)**
- Sent: "what is the capital of australia, and also remind me friday 9am to submit the form"
- Bot: "Step 2 ... I've noted a reminder for Friday, November 13, 2026, at 9:00 AM ... (You can also use the /schedule command ...)". `/api/reminders` afterwards had NO such reminder. Took 61 s (front desk 12 s, planner 37 s).
- Should: set the reminder for real (a split step must go through the same reminder code) or say it could not. Never claim it is saved.
- Owner: `planner.js` (step type "general" lets a model write prose about a reminder), `core.js`/`router.js` (split path does not reach the reminder action).

**H2. Telling Bot where you are is ignored, even when it just asked**
- Sent: "my last linear algebra lecture was lecture 1" / "it was last Thursday" (answer to Bot's own question "Which date was it?") / "my last Calculus lecture was Monday" (the exact example in the page's welcome note).
- Bot: the same status block again ("0 lectures held so far ... I do not know where you are in this course yet ... where are you?"). Nothing saved. Repeated for 4 different messages ("I understand everything already", "my homework is due next Sunday" got the identical block).
- Should: save the position, or say why it cannot ("I have no timetable for this course, so I cannot place lecture 1; I saved it as your position anyway" / "I have no course called Calculus"). A question from Bot must be able to be answered.
- Owner: `study-positions.js`, `study-coach.js` (answerStudy fallthrough).

**H3. A plain question invents an assignment card**
- Sent: "Which course do I have a homework for?"
- Bot: "I read this as an assignment for Linear Algebra Demo: 'Linear Algebra Demo Assignment' ... needing: Basic linear algebra concepts, Reading comprehension of course requirements. Confirm?" (made up from nothing; Homework 1 was already saved).
- Should: answer "Homework 1 in Linear Algebra Demo, no due date" from the saved list. Questions must never create a proposal.
- Owner: `study-coach.js` (proposal path), `router-brief.md` (course action for a question about the tracker).

## What worked well
- Simple things are fast: greeting 3-5 s, 17*23, reminders 5 s, calendar cards 4-5 s with correct weekday/date ("next Tuesday" from Sat 7 Nov -> 10 Nov), Hebrew calendar card correct (Wednesday 10:00-11:00).
- "change that dentist thing to 5pm" correctly made a new full card.
- Follow-up question after a course answer ("and why is the determinant zero then?") kept context.
- Four messages sent at once: fast ones finished in 6-15 s while the slow one ran (49 s).
- Memory: "remember that ..." saved and "what do you know about me" listed it. "Make your page dark mode" went to Improve Bot with a confirm step. Link message went to web research and honestly said example.com is a placeholder.
- Injection-style text inside an uploaded file was ignored (it was only filed).
- Browser at 375 px: no horizontal page scroll (documentElement.scrollWidth = 375), Study page readable. 55 buttons on the page are under 32 px in one dimension (not checked individually; many are probably icon buttons).
