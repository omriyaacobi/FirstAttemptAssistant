# Night build of the thread page: decisions made while Omri slept (2026-11-07)

Omri could not answer, so each unclear point was settled with the safest option that keeps moving. Change any of them by telling me.

1. **No server file was touched.** The server cannot serve a new `.js` file (only the fixed names in `STATIC`), so the new page code is a second inline `<script id="threadScript">` in `public/index.html`. It shares the page's own helpers. With `BOT_THREAD` off, `window.botThread.start()` is never called and the old code runs as before.
2. **Switch-off safety.** The server's `/api/session` says `thread: true` only when the switch is on. Only then the start-up code calls `botThread.start()`; otherwise it calls `showEmpty(); loadChats(); pollJobs();` exactly as before. The old `pollJobs` returns at once when `session.thread` is set, so the two pollers never both run.
3. **A bug in the old page found and fixed.** The "Restart Bot" button sat in the HTML AFTER the script that wires it, so `$("restartTop").addEventListener` threw and stopped the rest of the script (in the browser pane the whole start-up never ran, also for the unchanged page). The button now sits before the script. Looks identical (it is `position: fixed`).
4. **The old chat functions are replaced from outside**, not edited: `send`, `pollJobs`, `ensureLiveCard`, `updateComposer`, `loadChats`, `showEmpty`, `chatButtons`, `updateChatName` are re-assigned in `start()`. `renderResult`, `renderText`, `botCard`, `calendarCard`, `rememberButtons`, math, markdown, `logDetails`, the sources popup, Improve Bot, Quota, Restart, Push and the backup line are the old code, untouched.
5. **Layout.** One scroll, newest at the bottom. Messages are grouped into day sections (`Today`, `Yesterday`, then `Tue 3 Nov`); today and yesterday are open, older days are folded (tap to open, with a message count). "Load older messages" asks `GET /api/thread?before=<oldest>` for 50 more and opens the days it brought. The scroll position is kept when older messages are added.
6. **An answer sits under its question** through `replyTo`. If its question is on an older page that is not loaded yet, the answer gets its own group and moves under the question when that page arrives.
7. **Composer never locked.** Only the second while the message is being sent is "busy". A working card per running job sits under its own question: "Bot is thinking" (or "Waiting for a free slot"), the step text, the answer so far, seconds. The step text is whatever the server's `describeProgress` says, so "reading Calculus 2, lecture 5" shows only if the server writes it in the job log (that hook is in `study.js`, not done here).
8. **"Answer ready" chip.** When an answer arrives and you are not near the bottom, a round button sticks to the bottom of the scroll area; tapping it scrolls to the answer. It goes away when the answer is on screen.
9. **Route chip** is written from the answer's `topic` (course name from `topic` + the real course list, "Calendar", "Study", "Earlier chat", "General"). "Wrong? Ask again normally" appears for course, calendar and study answers. **There is no server option to force a route**, so it sends the same question again with one visible sentence in front ("Please answer this as an ordinary question, not from my course files, my calendar or my study plan."). A real `route` field on `/api/ask` would be cleaner (see "Needed from the server").
10. **Bot's questions and proposals.** A reply whose rule is "asked you a question" is drawn as a "Bot asks you" card with an Answer button (puts the cursor in the box). A reply that carries `result.proposal` (or `result.study.proposal`) gets "Yes, save it" / "No, drop it" buttons. **No server route exists to confirm a proposal**, so a tap sends the plain words "Yes, save it." / "No, drop it." as the next message; the study coach reads that as its `confirm` / `cancel` intent. The calendar Confirm card is unchanged (its own route).
11. **Trash.** Each message has a Delete button that is hidden until you tap the message (on a phone) or hover it (PC), so a long conversation is not a wall of buttons. Delete calls `DELETE /api/thread/<id>`; the message is replaced by one line "Message deleted. Kept for 30 days." with Restore (`POST .../restore`). **The server has no list of trashed messages**, so Restore is offered only right after deleting, in the same page session. A page for "Deleted messages" needs `GET /api/thread/trash`.
12. **Deleting a question leaves its answer** (the answer then stands alone). I did not make it delete both: a tombstone hides one message.
13. **Files and photos.** A picture still goes with the message (the page's own photo code, phone camera included). Any other file (PDF, pptx, docx, txt, md) opens a small dialog "Add this file to a course"; it uploads through the EXISTING route `POST /api/courses/<id>/files?name=` (so Bot's reading, the file list and the ticks work as today). The study coach's `onUpload` (assignment and lecture proposals) is not connected on the server, so no proposal card comes from an upload yet.
14. **Study page.** New sidebar button "Study" (the old "Courses" button text changes, with the switch on). It shows, for each course: where you should be, where you are, what is due, Bot's open question, files count, and a Files button. It reads `GET /api/study`, which does not exist yet; if it is missing the page says so and shows only the courses and files from `/api/courses`. The shape it reads (tolerant, every field optional): `{ courses: [ { courseId, name, shouldBe?, youAre?, held, understood, behind[], position{known,n,note}, assignments[{title,due}], topicsDue, question } ] }`, which is the tracker's `progress()` object plus a `question` string. The Files button opens the OLD Courses screen of that course (sources, ticks, reading status, upload, rename, delete). With the switch on its "Chats" column is hidden by CSS.
15. **Recall buttons** ("Open: <chat title>") no longer open an old chat as the current chat (that would wipe the thread). They open the old chat read-only in the sources popup.
16. **First-use notice** at the top of the conversation, once per device (`localStorage` `botThreadNotice`): what changed, where old chats went, how to go back (`BOT_THREAD=off` in `.env` and restart).
17. **Tap targets.** All new buttons are at least 44 px high; with the switch on the old source chips, the "What Bot did" summary, the mic and the language box also get 44 px. At 375 px wide nothing scrolls sideways (checked: page width 375).
18. **The "Don't split into steps" box stays** (it sends `noPlan`). The "Think harder" (`deeper`) box of course chats is gone in thread mode: nothing sends `deeper`.
19. **Unread dots and push per chat** are gone (there are no chats). While the page is visible the poll sends `?watching=thread`, so no push is sent to the phone.
