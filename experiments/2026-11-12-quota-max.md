# Quota max: where the quota goes, and how to get more messages a week (2026-11-12)

Goal (Omri): use Bot as much as possible each week without Bot getting dumb. Argon ends fast, agy's Claude Sonnet lasts
about 100 messages a week, and the last resort (Claude Code) shares the Claude Pro plan with Omri's own coding.

Status: **PHASE 1 (measure and plan) done. Nothing in Bot was changed. Waiting for Omri's OK before building.**

Scripts (both in `experiments/`):
- `quota-max-measure.js`: spends NO quota. Counts model calls from the thread files and replays real messages through the real
  `brain.js` with a fake model to measure the prompt.
- `quota-max-probe.js`: spends a little quota. Sends big or small prompts to one agy model and reads the pools before and after.

New word: a **token** is the unit models count text in (about 4 English characters, or about 1 Hebrew letter).

## 1. Findings

### 1.1 agy tells us the exact tokens of every call (we never read it)

In stream-json mode the last event of every agy call has
`"usage": {"input_tokens", "output_tokens", "thinking_tokens", "cache_read_tokens"}`. Bot throws it away today.
With it Bot can log the real cost of every answer.

### 1.2 Every agy call carries a fixed overhead of 8,200 to 12,500 tokens that Bot does not need

agy is a coding agent. Before our prompt it sends its own system prompt and the descriptions of **60 tools**
(browser clicks, run_command, write files, image generation ...). Measured with the prompt "Reply OK":

| model | input tokens for an EMPTY prompt |
|---|---|
| Gemini 3.8 Flash / Gemini 4 Argon | 8,200 |
| Claude Sonnet 5.5 inside agy | 12,500 (5,800 + 6,700 "cache read") |

Options that did NOT reduce it: `--mode plan`, `--sandbox`, `--disable-slash-commands`, `--effort low`, a `permissions.deny` setting.

**What does reduce it: a custom agent.** agy reads agent files from `<working folder>/.agents/agents/<name>/agent.md`
(a Markdown file; the top lists the allowed tools, the body is the system prompt), chosen with `--agent <name>`.
With an agent whose only tool is `search_web`:

| model | default | with the slim agent | saved per call |
|---|---|---|---|
| Flash / Argon | 8,200 | 2,080 | 6,100 tokens |
| Claude Sonnet in agy | 12,500 | 3,400 | 9,100 tokens |

Web search still works under the agent (checked with one real search). It is also SAFER: the model is no longer even offered
run_command, the browser or file writing. The file lives in Bot's own sandbox folder, so nothing in agy's global settings changes.
Not yet tested: answer quality of the real brain under the agent (agy's own system prompt is replaced by ours). That is the
first test of phase 2.

### 1.3 The pools charge by tokens, and the overhead is about half the bill

4 calls each, agy Claude Sonnet low, answer "OK" (so the cost is the input):

| prompt | tokens per call (input + cache read) | weekly pool | five-hour pool |
|---|---|---|---|
| 40,000 characters (like a real brain prompt) | 20,700 + 6,700 | 67 -> 64% | 95 -> 88% |
| empty | 5,800 + 6,700 | 64 -> 62% | 88 -> 85% |

So an EMPTY call still costs about 0.5% of the weekly Sonnet pool, and a real one about 0.75%. Roughly: the weekly
"Claude and GPT" pool is about 3 to 4 million tokens, the five-hour window about 1.5 million. (Percent readings are whole
numbers, so these are rough.) Cache-read tokens seem to be charged like ordinary ones.
Argon, from the 2026-11-11 test (11 calls for 2%): 1% is roughly 115,000 tokens, so its weekly pool is about 3 times Sonnet's.
The Flash pool ("Gemini Models") is at 92% late in its week: Bot hardly uses it.

### 1.4 The brain's prompt: about 40,000 characters (13,000 tokens) on EVERY round

Replay of the 46 real messages of 2026-11-11 and 11-12 (median 39,800 characters, largest 61,800; Omri's own message: median 98):

| part of the prompt | share | mean characters |
|---|---|---|
| course in focus: assignment text 4,250 + linked-folder code 4,600 + matching pages 5,700 | 36% | 14,600 |
| recent conversation (incl. 1,700 of daily notes) | 27% | 11,000 |
| briefing (`brain-brief.md`) | 22% | 9,100 |
| time + profile | 7% | 2,800 |
| course list | 5% | 2,200 |
| calendar + reminders | 2% | 800 |

- **45 of 46 messages had a "course in focus"**: a course stays in focus for 6 hours, so "thanks" or "remind me at 9" also
  carries the assignment, Omri's code and course pages.
- Every tool round sends the WHOLE prompt again plus the tool results.

### 1.5 Model calls per message

From the log lines saved with each answer:

| day | messages | brain calls | calls per message | 1 / 2 / 3 / 4 calls |
|---|---|---|---|---|
| 2026-11-11 | 38 | 55 (all Argon) | 1.45 | 27 / 7 / 2 / 2 |
| 2026-11-12 (so far) | 9 | 13 (9 Argon, 4 agy Sonnet) | 1.38 | 6 / 1 / 1 |

Most used tools on 11-11: project_read 15, course_read 8, course_search 6, course_note 5.

### 1.6 What one everyday message costs today

One call = overhead + prompt. Argon: 8,200 + 13,000 = about 21,000 tokens. Sonnet in agy: 12,500 + 13,000 = about 25,500.
Times 1.45 calls, plus tool results: about 33,000 (Argon) or 40,000 (Sonnet) tokens per message.
- Argon: about 0.3% of the week per message -> about **330 messages** if nothing else used Argon.
- agy Sonnet: about 1.1% per message -> about **90 messages** (matches Omri's "about 100").

Other things that draw on Argon and are NOT chat: tutoring (Argon medium, thinks more), reading cut PDFs, photos, the daily
summary, position/standing readers, the Argon editor of Improve Bot, and every test a Claude Code session runs against the real
brain. This week's fast drain is partly those tests (a full 7-message test run is about 2% of Argon or 7% of Sonnet).

## 2. Ways to stretch (saving and risk)

| # | change | saving | risk to answers |
|---|---|---|---|
| A | **Slim agent** for the brain's agy calls (only `search_web`) | 6,100 tokens per Argon call (-29%), 9,100 per Sonnet call (-36%) | low; must pass the test set first (new system prompt) |
| B | **Token log**: read agy's `usage`, print it with "which model answered", keep a per-day total | none by itself; makes every later step measurable | none |
| C | **Smaller context**: (1) focus material only when the message is about the course work, decided by the search score that already exists, not by keywords; otherwise only the file list, and the model fetches with tools. (2) recent conversation 9,000 -> about 5,000 characters. (3) linked-folder code: file list + the 1 newest file, not 3 | about 3,000 to 5,000 tokens per call | medium: some messages need one more tool round; a follow-up may lose an older turn. Needs an A/B on real messages |
| D | **Pace the week**: instead of "Argon until 25%, then Sonnet", prefer the pool that is ahead of its weekly pace (percent left vs. share of the week left) | no extra capacity; Bot stops burning one pool by day 2 and both pools get used fully before they reset | none for quality; the answering model changes more often |
| E | Move **non-answer jobs** off Argon to Flash medium first: daily summary (already quote-checked by code), position/standing readers (closed fields checked by code) | small (a few % of Argon a week) | low; these outputs are validated by code |
| F | **Cheap first pass** by Flash for trivial messages, the model itself deciding to hand up | maybe 20-30% of messages leave Argon/Sonnet | touches the agreed rule "Flash never writes the brain's answers"; needs a real Hebrew/English test set first. NOT recommended now |
| G | Google AI Studio API key (own free quota) | today's free tier looks tiny: recent reports say about 20 requests a day for Gemini 3.8 Flash, 0 for Argon and Pro (older pages say 1,500; unverified, check the rate-limit page in AI Studio) | free-tier prompts may be used by Google to improve models, and the brain's prompt holds calendar titles and the profile. NOT recommended |
| H | Claude Haiku (Pro plan) as a step before Claude Code Sonnet | spares some of the Pro plan in the last resort | unknown quality for the brain; only matters when both agy pools are empty. Later, if needed |
| I | Fewer tool rounds, lower effort | effort is already "low"; rounds are already 1.45 | cutting rounds makes answers worse. Skip |
| J | Caching repeated lookups | calendar is already cached; separate agy calls share no cache | nothing to gain |

## 6. Notes for whoever builds this

- Git Bash turns `/usage` into a path: use `MSYS_NO_PATHCONV=1 agy -p "/usage"` (or PowerShell).
- An agent file: `---` / `name:` / `description:` / `tools:` (a YAML list) / `---` / body = system prompt. agy's docs warn that
  a misspelled tool name can make the run hang; `search_web` is the spelling agy lists in its `init` event.
- `agy agents` printed nothing for a workspace agent, but `--agent bot-brain` worked and the `init` event showed `agent=bot-brain`.
- The `init` event still LISTS 60 tools with an agent; the input tokens are what dropped.
- The warm pool (`warmagy.js`) starts agy before the question arrives: `--agent` must be added to its start arguments too.
- Sources for G: https://imisofts.com/blog/gemini-api-free-tier-limits/ , https://tokenmix.ai/blog/gemini-api-free-tier-limits
  (they disagree). agent docs: https://antigravity.google/docs/subagents , https://antigravity.google/docs/cli/commands/agents
