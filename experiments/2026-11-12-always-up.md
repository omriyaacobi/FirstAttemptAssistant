## What was built
- `watchdog.cmd`: one quick check. Bot answers on 3000 -> nothing. Nothing listens on 3000 -> start Bot (no window).
  Port held but no answer for about 1.5 minutes (Bot hung) -> stop ONLY the process that holds port 3000; Bot's own
  starter loop (`start-web.cmd`) starts it again, and if that loop had given up, the watchdog starts Bot itself.
  `data\stay-stopped` (left by `stop-bot.cmd`) -> leave Bot stopped; starting Bot yourself removes that file.
  Every action is one line in `data/bot.log` starting with `[watchdog]`.
- `bot-watchdog.vbs`: runs `watchdog.cmd` with no window (a `.vbs` file run by `wscript.exe` has no console; `//B` means
  that even an error never pops up a box, so nothing can appear over a game).
- `autostart.ps1` + `install-autostart.cmd` / `remove-autostart.cmd`: make or remove the Windows scheduled task "Bot".
  `autostart.ps1 show` prints the exact task definition without making anything.
- Tests: `tests/watchdog.test.js` runs the real `watchdog.cmd` from a temp copy on a free port: answering server,
  nothing listening, the stay-stopped mark, and a HUNG server (a separate node process that accepts and never answers):
  it was stopped and Bot was started. The hidden VBS -> cmd chain was also run once by hand on a free port.

Why a scheduled task and not a Startup-folder shortcut: a shortcut runs once at login and never again, so a crash loop
that gave up, or a hung Bot, would stay down until the next login. The task runs at login AND every 5 minutes, never
twice at once, as you with normal rights, only while you are logged in (it needs your `claude` login, `agy`, Chrome
and your files, which only exist in your session).

Terms: **Task Scheduler** is the Windows program that runs things at set times or events (open it from Start: "Task
Scheduler"; the task is in "Task Scheduler Library" with the name Bot). **Watchdog** = a small checker that restarts a
program that died or froze. **Hung** = the process still exists and holds the port, but answers nothing.

## Can Bot run while the laptop is OFF?
Short answer: not without a second computer. Bot is a program running on the laptop; off means no Bot. What Bot needs
on whatever machine runs it: the logged-in `claude` CLI (Pro plan), `agy` logged in to Google, the Google Calendar
login, `data/`, your course and assignment folders, and Chrome logged in to BGU Moodle with the extension.

| Option | Cost | Effort | What breaks or changes | Verdict |
|---|---|---|---|---|
| (a) Keep the laptop on and plugged in (now + this branch) | electricity only: an idle laptop with the screen off uses roughly 5-15 W, a few shekels a month | done | down when you shut it, take it away and close it in a bag, or during an update restart (fixed by step 2) | **the right choice now** |
| (b) Wake-on-LAN / wake timers | free | medium, unreliable | Wake-on-LAN needs a "magic packet" from a device on the SAME home network; the phone over Tailscale cannot send it, and Wi-Fi wake on Modern Standby laptops is unreliable. Wake timers only wake at set times, not when you message. Does nothing when the laptop is fully off or not at home | not worth it |
| (c) An always-on mini PC or an old laptop at home | a used mini PC roughly 400-1000 shekels; power a few shekels a month | a day: install Node, git, Tailscale, log in to `claude`, `agy`, Google, Chrome + Moodle; copy `data/` | your files and code folders live on the laptop (Linked folder would need a sync like OneDrive); Moodle needs Chrome logged in THERE; one more machine to update | **the real "always up" option** if (a) is not enough |
| (d) A cloud VM (a rented computer in a data center) | roughly $5-20 a month for a small one | high | `claude` and `agy` logins on a server you must secure; your study files and calendar tokens leave your PC; BGU Moodle from a data-center address will most likely be blocked (Akamai already blocks scripts) and Chrome would need a desktop there; a public server must be locked down | no, for now |

Recommendation: (a) now. If being down while the laptop is away becomes a real problem, (c) with an old laptop is the
cheapest step; plan it in its own chat (it is mostly setup, little code).
