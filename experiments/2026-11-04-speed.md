# Why is Bot slow? (measured 2026-11-04)

All times are real runs on Omri's PC (one run each, so treat them as rough).

## Where a message spends its time today

```
quota lookup (agy /usage)      ~3.6 s   runs BEFORE the front desk, once per 5 min
front desk (Flash high, JSON)  11-15 s  every message
destination model              5 s .. several minutes (Argon medium: 155 s in one saved chat)
+ every failed model in a fallback chain adds its own time before the next one starts
```

## Measurements

| What | Time |
|---|---|
| `agy -p /usage` (quota) | 3.6 s |
| `agy` Flash high, "Reply with just OK", empty folder / Bot folder | 6.1 s / 7.1 s |
| `agy` Flash medium, same | 5.4 s / 5.7 s |
| Front desk, Flash **high**: "7 times 8" / "python palindrome" / "remind me tomorrow at 9" | 11.3 / 15.0 / 12.5 s |
| Front desk, Flash **medium**: same three | 7.6 / 8.7 / 8.6 s |
| `claude -p --model sonnet` | **fails in 1.3 s: "OAuth session expired"** |

The front desk made the same decision with high and medium on all three (answer / delegate to claude-sonnet / remind). Three samples is not proof; test more before switching.

Saved chats show the expensive cases: one "quick" task took 106 s because two Gemini models returned empty answers before Sonnet took it; one hard task took 556 s after Argon returned empty and Opus failed.

## Findings

1. **Every `agy` call costs about 5 s before the model even thinks** (starting the CLI, logging in, connecting). Fewer calls per message = faster.
2. **Front desk on Flash medium saves about 4-6 s on every message** (35-40 %). Omri's idea is right, but it is not enough alone.
3. **The quota lookup is on the critical path.** `core.js` waits for it before asking the front desk. It could use the last known numbers and refresh in the background: about 3.6 s saved on the first message after each 5 minutes.
4. **The Claude CLI is logged out.** Everything that goes to Claude (code tasks, the default/fallback Sonnet, Opus) fails and falls down the chain, which costs time and gives worse answers. Fix: run `claude auth login` again (Omri's step).
5. **Models run in Bot's own project folder.** `claude -p` and plain `agy -p` are agents: in a project folder they may read files and load project context. That is slower (6.1 vs 7.1 s for agy) and a likely cause of the "empty answer" failures. Running them in an empty folder (and Claude with `--tools ""`) is faster and safer.
6. **No timeouts.** A model that hangs blocks the whole chain. Per-model time limits (e.g. Flash 60 s, Argon 3 min) make the fallback start sooner.
7. **Argon medium is very slow** (155 s). For "hard" tasks Argon low is probably good enough most of the time.

## Plan (in order of value for effort)

1. Omri: `claude auth login` (fixes the failing Claude route).
2. Front desk -> Flash medium, after checking ~15 varied prompts give the same decisions.
3. Quota lookup off the critical path (cached value, background refresh).
4. Run every model in the empty sandbox folder; Claude with no tools.
5. Per-model timeouts so fallbacks start sooner.
6. "hard" -> Argon low by default; Argon medium only when the front desk says it is really hard.
7. Bigger, later: show the answer while it is being written (streaming), or a Gemini API key (no 5 s CLI start, but separate quota).

Expected: a simple question from ~20 s to ~10 s; a delegated task saves ~10 s plus no more failure cascades.
